## 2. Judgement of the intentional decisions

(a) Default `classic`, BA skills open `guided`: reasonable for alpha.48 compatibility, and the skill and the command catalog now say so. It remains a soft guarantee: it depends on the model following one sentence; a user gets no signal that their item is ungated. I would accept it only with the docs' statement kept and a visible `mode` in the briefing (the briefing does carry `mode`).
(b) Documenting D16/D17/D20 residuals: acceptable for D17 and D20. For D16 the limit is real (labels satisfy the check, `r8.mjs`) and the doc sentence overstates what is detected; wording should say "labels only".
(c) D13: acceptable. Link 10 min + per-load save tokens + Origin required is a sound reduction. The multi-use link and reusable save token still make replay possible for anyone who obtains the link in that window.

## 3. New defects

**N1 - blocker - A repository `.env` re-opens D01.** `loadPraxisDotenv(repo)` (Core `cli/src/operations.ts:279-291`) loads `.env`/`.env.praxis`/`.env.praxis.local` from the working repository into `process.env`; its forbidden-prefix list is `PRAXIS_APPROVAL_`, `PRAXIS_ALLOW_`, `PRAXIS_FIXTURE_`, `PRAXIS_TEST_`, `PRAXIS_STATE_HOME` and does not include `PRAXIS_REVIEW_`. `review-service.ts` (`openInBrowser`, `renderReviewTool`) honours `PRAXIS_REVIEW_NO_BROWSER=1` by writing the full token link to `<repo>/.praxis/workflow/reviews/<WI>/<view>.url`. Repro (`/tmp/q2/h/r1.mjs`): write `.env` with `PRAXIS_REVIEW_NO_BROWSER=1`, call `praxis_review_render`, read the `.url` file, fetch it, POST `acceptAll` with the page's save token and `Origin`: 200, `requirements_review` accepted as `html-review`. Any agent that can write a file in the project (every coding agent) can do it; no shell needed. Fix direction: forbid `PRAXIS_REVIEW_` in dotenv, and never write the link to the repository (use the user's state home with 0600, or an environment-only switch).

**N2 - minor - Secret handling for prototypes got weaker for what the heuristic misses.** The prototype subtree is now stored unredacted (`redactState`), and only `mock`, `endpoints`, `notes` are scanned for a short list of token shapes. `r3.mjs`: base64 and 40-hex secrets, a space-split `sk-` key and a plain password in mock rows are accepted and stored; a `Bearer ...` token in a screen title or an `sk-`/`ghp_` string in a title/element label is accepted and stored (titles, labels, descriptions, state messages, feedback comments are not scanned). Before, any 40+ character token-like string was redacted everywhere. The refusal also rejects `Bearer <20+ chars>` placeholders.

**N3 - minor - `openedInBrowser` can be true when nothing opened.** `r10.mjs`: with an opener that exits 1, the result says `openedInBrowser: true` and tells the agent the page "was opened in the user's browser" (`spawn` pid defined). Headless Linux (`xdg-open` without a display) will look the same, and the offline-copy fallback is never offered. Also every `praxis_review_render` call (agent-callable, no throttle) launches another browser tab and another server-side session (3 calls -> 3 launches).

**N4 - minor - The dialog truncates what it shows.** `r9.mjs`: statement edits are shown cut at 80 characters, comments and waiver reasons at 80-120 although the schemas allow 1000-4000; requirement-level `scopeNote` and `comment` are not listed at all. The approved batch is bound to the full text, but the user sees a prefix.

**N5 - minor - Stale skill text.** `story-plan/SKILL.md:22` and `stories-review/SKILL.md:25` still tell the agent to waive gaps with `waive-coverage`, which is now refused for agents; only the prototype skill describes the new user-only path.

**N5b - minor - Misleading error for state files.** `t39.mjs`: a state file with an unsupported version produces "the command is invalid: version: ... praxis_workflow_commands lists every action" (the zod error of the stored state is explained as a command error).

**N6 - minor - `artifactHistory` is bounded by count, not size.** `r5.mjs`: 200 edits of a 20 KB requirement -> 150 snapshots, item file 3 MB; a large requirement (thousands of criteria) multiplies that by 150. Prototype snapshots (10) carry full mock data.

Not tested: behaviour of a saved page after the link token expires, eviction of the 21st save token, real browser focus behaviour for D12, a live `tools/list` for the annotations, and the `.mcpb` that is modified but uncommitted.
